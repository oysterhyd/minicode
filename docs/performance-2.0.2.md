# 2.0.2 代码简化与性能优化

以 2.0.1 的 `229c1b6` 为对照，逐功能链路审查 Rust Agent、原生 Desktop、Ink TUI 与发行流程。优化集中在重复数据库操作、JSON 所有权、流式缓冲和 Markdown；界面布局与交互、权限、工具输出预算、会话 schema 7 和原更新公钥保持兼容。

## 简化方式与复杂度

两套逐字段数据库更新循环合并为一个帮助函数，8 个字段只执行一次 UPDATE；2000 条消息的重写去掉 2000 次 MAX(seq) 查询，INSERT 语句只准备一次。SQLite 的索引写入仍有自身的树结构开销，不把这项变化表述为全部操作从 O(n log n) 变成 O(n)。事务和持久同步强度未降低。

上下文估算仍按输入线性遍历，但 JSON 字符串的临时堆空间由 O(S) 降为常量，递归栈取决于 JSON 深度。请求组装与恢复通过移动已有对象，消除与消息／事件长度成正比的额外副本。MCP 单分片有 C 字节、L 行时，原先每行 drain 搬移剩余数据，最坏为 O(C×L)；现在该分片的扫描与搬移为 O(C)。

Markdown 解析器初始化从每次文档一次变为每进程一次。代码高亮保留结果所需的数组，去掉 token 分行的中间数组。TUI 30,000 条已完成记录加一条 pending 的完成事件，额外 FeedItem 对象由 30,001 个降为 1 个；处理仍要遍历记录，没有声称整个 TUI 渲染成为 O(1)。

11 个核心文件新增 208 行、删除 121 行，净增 87 行。本轮没有减少总代码行数：减少重复处理后，也增加了字段投影、所有权转移和缓存边界的显式实现。逐文件计数见原始指标的 `source_diff`；测试、基准与发行验证脚本不计入这些数字，不把压缩发行 JS 的行数算作源码简化。

## 测量方法

Windows 11 26200 x64，Ryzen 7 8845H（8 核／16 线程），约 15.3 GiB 可见内存；Rust 1.99.0、Go 1.27.1、Node 22.22.0。源码对照使用同机同工具链构建。每项保留 7 次样本及中位数，Agent 每对样本交替先后顺序。性能测试期间不并行编译或运行其他测试。

Rust / Go 的“分配字节”是一次操作累计请求的堆内存，包括 realloc；它不是进程峰值或最终保留内存，Rust 指标也不包含 SQLite 的 C 分配。Agent 内存是 Windows Get-Process 的实际工作集／私有字节／峰值工作集。测试驱动按分片组装 NDJSON，避免驱动自己反复扫描 20 MB 字符串。

请求组装夹具有 1000 条、每条 10,000 字符的消息，只构造请求，不调用在线模型。上下文夹具有 800,000 个 Unicode scalar、1,500,000 个 UTF-8 输入字节；旧原始记录键名的 `1m` 是标签，具体夹具以源码为准。消息重写和计数器使用内存 SQLite，隔离 SQL／序列化开销。长会话用 2000 条约 10 KB 消息；恢复统计还加入 2000 条约 10 KB 事件。25 轮任务调用 fake Provider、读取文件 48 次。

上下文估算的分配次数为 1837 → 29，原生小段 Markdown 为 231 → 71。长会话的最终私有字节为 31,571,968 → 30,941,184 B，而最终工作集为 34,619,392 → 35,438,592 B；显著下降的是恢复过程中峰值，不能据此声称所有阶段都少用 29% 内存。消息重写分配 256,000 → 256,056 B，8 字段更新为 674 → 700 B：语句缓存和参数集合有少量空间成本。

冷启动 27.238 → 27.492 ms，状态热轮询 0.0650 → 0.0648 ms，基本持平。25 轮离线任务最后一组为 169.230 → 158.990 ms（6.05%），其他试测中也出现持平；它是轻负载，不能用大 JSON 微基准的百分比代表整次任务速度。高亮的耗时范围有重叠；其主要确定收益是去掉每个 token 的中间分行数组。

同机 Agent 文件为 10,612,736 → 10,025,984 B，减少 5.53%。发行 TUI 压缩 2251 个 JS 文件，减少 2,630,667 B；另外删除一个 344,546 B 的 Flow 类型文件。旧版已有的声明／source-map 裁剪收益不重复计入本次改进，Git / Node 和运行依赖保持完整。公开安装器体积按正式发行资产单独核验，不用源文件缩减量推算压缩包大小。

## 复现入口

- Rust：`cargo run --release --locked --example performance_hotpaths -- output/hotpaths.json`。
- Go：在 `desktop/native` 执行 `go test -run '^$' -bench '^BenchmarkOptimization202$' -benchmem -benchtime=500ms -count=7 .`。
- TUI：`node tui/node_modules/tsx/dist/cli.mjs tui/scripts/benchmark_202.ts . output/tui.json`。
- Agent：`node scripts/benchmark-agent.mjs --baseline <旧版程序> --agent <新版程序> --samples 7 --kinds cold,turns,history,poll,stats --output output/agent.json`。

源码对照把同一份 `examples/performance_hotpaths.rs` 和 `desktop/native/performance_202_test.go` 复制到 2.0.1 的独立工作树再构建。临时工作区、假模型脚本和数据库由驱动生成。Rust 示例与 UI 基准只属于开发／验证工具，不进入安装包。

## 回归验证
