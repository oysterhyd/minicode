# MiniCode 三端交互规范

适用版本：3.0.3，阶段 7。本文描述实际实现，验收证据见 [阶段报告](stage7-completion.md)。Bridge 协议仍为 2；新增事件/状态字段可选，客户端忽略未知事件，`initialize.capabilities` 声明新增能力。

## 会话、恢复和清屏

- `/resume ID`：完整 ID 精确匹配优先；否则接受任意非空、唯一前缀。不存在和歧义均报错，不自动选第一个。显示缩写不替代真实 ID。
- `/resume`：TUI/CLI 列出最近会话及完整 ID，通过再次输入命令选择；Desktop 打开会话选择器。
- 恢复原会话消息、实际用量、项目约定与累计 token 预算。CLI 显式预算（包括 0）优先于保存值；轮数、时间是每次 run 的限制。
- `/new`、`/clear`：开启新上下文，保留旧会话及文件变化，可用 `/resume` 恢复。运行中拒绝重置，须先取消并等待收尾。
- `/cls`：只清显示，不改变持久化上下文。TUI 不擦除原生滚屏；恢复历史仍能看到原消息。**迁移：旧版 `/clear` 的清屏功能改用 `/cls`。**
- 编辑重发：TUI 空闲双 Esc、Desktop 用户消息的“编辑并重新发送”把原消息复制到草稿；提交后追加新消息。原消息和文件变化保留，文件撤销属于后续 G3。

## 输入状态与按键

普通输入按审批 → 弹窗/菜单 → 运行/取消 → 草稿/历史 → 空闲处理；专门的取消/退出组合键可直接取消运行。审批快捷键只指向第一张待处理卡片，处理中不落到下一张。

| 操作 | TUI | CLI chat/run | Desktop |
| --- | --- | --- | --- |
| 取消当前 run | Esc（先处理审批、菜单）、Ctrl+C | Ctrl+C | 停止按钮、Ctrl+.（macOS Cmd+.） |
| 取消收尾期间强退 | 再次 Ctrl+C 退出 TUI | 再次 Ctrl+C，退出码 130 | 窗口退出；不占用复制快捷键 |
| 空闲 Ctrl+C | 有草稿先清空；空草稿两秒内再次按下退出 | 编辑器取消当前行；两秒内再次中断退出 | 原生复制 |
| Esc | 拒绝审批、关闭查看器/菜单、退出斜杠子菜单、运行时取消一次 | 行编辑器操作，不作为取消约定 | 拒绝首张审批或关闭弹窗/补全 |
| 编辑上一用户消息 | 连续两次 Esc，间隔 ≤400ms，其他按键重置判定 | 上键历史后编辑 | 消息编辑按钮 |
| Enter | 提交；忙时非空消息插话；空输入不取消 | 提交；忙时见队列/审批边界 | 提交；忙时非空消息插话；空输入不取消 |
| 多行 | Ctrl+J | Ctrl+J（TTY） | 原有多行编辑器 |
| 退出 | Ctrl+D、Ctrl+Q、`/exit` | Ctrl+D/EOF、`/exit`、`/quit` | 关闭窗口 |

TUI 普通草稿单 Esc 不清空；斜杠草稿先退出命令模式。运行中双 Esc 只发一次取消，不同时进入历史编辑。开始编辑不自动提交。

TUI 上下键在首/末行浏览历史并恢复原草稿，斜杠菜单先导航候选；`@` 文件候选使用 Tab 补全。CLI TTY 使用持久化历史、光标编辑、文件/命令 Tab 补全；管道维持逐行脚本兼容。

Bracketed paste 视作一次输入。TUI ≥4000 字符或 ≥20 行折叠为 `[paste:N]`，`/paste N` 预览、`/paste N cancel` 取消，提交时无损展开。`/attach "path with spaces.png"` 调用共享 `importAttachments`，`/attach clear` 移除待发送附件。图片采用可移植路径导入，不假定终端提供二进制剪贴板；失败保留可恢复草稿与附件。

## 审批

统一含义：Y“本次批准”、A“本会话允许规则”、P“写入项目规则”、N“拒绝”；TUI/Desktop 也可 Esc 拒绝。只有服务端提供可记住规则时才提供 A/P。工作区信任卡使用“信任并启动”，绑定插件指纹，不提供工具规则的“始终允许”。

CLI 显示请求新生成的确认码，批准必须输入 `y CODE`；会话/项目允许分别为 `a CODE`、`p CODE`。裸 `y`、旧码、未知文本不能批准，`n`/`no` 拒绝，EOF 拒绝。确认码同时保护 TTY 与管道的预输入边界。

审批期间普通文字不被当作拒绝答案或静默丢弃：chat 保留到后续输入；单次 run 将已读取的普通待提交文字保存为暂停 follow-up，并打印恢复方式。预输入斜杠命令明确报告未执行。连续审批只处理首项，每项有独立确认码。

## 服务端消息队列

`messageQueue` 能力提供 `enqueuePrompt`、`listQueue`、`deleteQueuedPrompt`、`resumeQueue`。每会话最多 100 条，以稳定消息 ID 标识；接受、消费、删除均持久化，旧会话格式兼容。

- `steer`：工具结果持久化之后、下一次模型请求之前追加用户消息；已经发出的请求不变。该模式内部按接受顺序处理。
- `followUp`：当前 run 正常完成后自动启动下一 run；该模式内部按接受顺序处理。新 run 有新 runId。steer 的工具边界优先于 follow-up 的完成边界，不承诺两种模式混排时全局 FIFO。
- steer 若没有下一工具边界，正常完成时作为下一 run 执行；剩余可执行消息按接受顺序启动。
- 用户消息和 `queue_consumed` 在一次 checkpoint 中提交，避免重启后重复插入。取消、失败、重启后的未消费队列默认暂停，必须显式恢复，不自动重试副作用。
- 队列属于会话。切换会话只切显示，不搬运队列、不取消其他会话任务。已消费/开始执行的消息不可删除；删除与消费由服务端裁决，界面刷新真实状态。

三端 `/steer 文本` 插话，`/follow 文本` 完成后继续，`/queue` 列出状态，`/queue cancel ID` 删除未消费项，`/queue resume` 继续暂停项。非法参数报用法错误。运行中普通消息默认为 steer；CLI 审批期间普通文字按审批边界保留。

TUI/Desktop 握手有该能力时只提交服务端队列，不在 run_done 后再次调度；旧 Bridge 缺少能力时保留原客户端 follow-up 降级，不能冒充实时 steering。旧客户端忙时 `sendPrompt` 仍收到原有拒绝。

## 输出、任务与状态

默认 TUI 使用普通终端滚屏：完成条目通过 Ink 公开 `renderToString`/`useStdout.write` 输出一次，活动树仅保留有界内容；不启用备用屏或鼠标捕获，终端负责原生选择、复制、回滚。`/history` 分页读取更早历史并追加到滚屏，不改写已经输出的内容。嵌入 App 可保留旧视口适配。

Ctrl+R 折叠/展开实时 reasoning 末尾 8 行；Ctrl+O 切换工具预览；Ctrl+F 查看最近归档完整输出：每页最多 20000 字符，N/P 翻页，方向键/PageUp/PageDown 滚动，R 重试，Esc 关闭。仅保存当前页和偏移栈，失败保留内容并显示错误。CLI 默认工具预览最多 10 行/2000 字符，错误单独保留，`-v`/`--verbose` 查看完整输出。

两端常驻卡展示真实任务状态，最多 4 条，`/tasks` 查看完整数据；`task_*` 结果触发独立刷新，不重建 transcript。仅使用现有任务模型，不提供 G4 高级编辑接口。

`MINICODE_STATUS_FIELDS=model,effort,context,turns,budget,cost,branch,elapsed` 配置状态栏；默认 model/effort/context。预算显示所有正值限制，分支来自 Git 状态（2 秒缓存）；费用无可核实价格时显示不可用。缺失字段安全降级，窄屏截断。

## 共享命令

| 命令 | 实际行为与边界 |
| --- | --- |
| `/cost`、`/context` | 实际 token 统计、运行时上下文估算；无定价不推算费用；历史仅加载摘要时上下文估算可暂为 0 |
| `/doctor` | 本地版本、OS、工作区、模型及 Git 可用性，不调用付费 Provider |
| `/init` | 新建基础 AGENTS.md，`create_new`，存在即报错，不覆盖 |
| `/agents`、`/mcp` | 已配置项；TUI `/mcp` 复用现有发现页面；配置存在不代表连接成功 |
| `/memory`、`/tasks` | 现有真实存储，完整能力分别由 S3/G4 演进 |
| `/export [path]` | 当前会话和消息的 JSON；限制工作区内，新建而不覆盖 |
| `/undo`、`/rewind`、`/fork` | 明确报告 G3 依赖，尚不执行回滚/分叉 |
| `/skill [name \| on name \| off name]` | 统一空白分词；缺名称/多余参数报用法；保留名称大小写 |

无参数命令拒绝多余参数，帮助来自共享 `agent/assets/commands.json`；客户端可提供原生选择器。GUI 的复制、窗口退出与终端信号采用平台映射，业务语义保持一致。
