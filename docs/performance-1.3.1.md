# MiniCode 1.3.1 代码审查与性能优化

本次保留现有功能、交互和布局，集中处理重复遍历、重复解析、无界临时分配，以及动画触发整棵界面重建的问题。基线为 v1.3.0（`a65a99b2a2e64484a37d76e953ec8e8c32b75127`），测量日期 2026-10-11，交付日期 2026-10-12。

## 实测结果

下表是固定本地数据集的中位数。Go 为每组 100 次、独立重复 5 组；Python / TUI 为 7 组。侧栏与 TUI 在同一进程中执行保留的旧算法与新算法，其余使用相同测量代码分别运行基线和新实现。

| 工作负载 | v1.3.0 | v1.3.1 | 时间下降 |
|---|---:|---:|---:|
| 10,000 会话、200 工作区的侧栏分组 | 11.195 ms | 1.315 ms | 88.3% |
| 2,000 消息与事件不完全匹配的历史恢复 | 52.377 ms | 0.872 ms | 98.3% |
| 2,000 消息正常匹配的历史恢复 | 1.550 ms | 1.178 ms | 24.0% |
| 30,000 条已有消息后追加一条 | 0.472 ms | <0.001 ms | >99% |
| 24 KB Markdown 已缓存的完整无窗口渲染帧 | 2.698 ms | 2.423 ms | 10.2% |
| 24 KB Markdown 分块 | 0.032 ms | 0.023 ms | 29.5% |
| 5,000 事件的统计首次读取 | 139.198 ms | 25.982 ms | 81.3% |
| 同一统计、没有新增事件的刷新 | 126.788 ms | 0.006 ms | >99% |
| 已有 5,000 任务时新增独立任务 | 12.180 ms | 0.018 ms | 99.8% |
| 20 MB 附件摘要计算 | 13.304 ms | 8.568 ms | 35.6% |
| TUI 从 10,000 条无展开内容的工具记录查找可展开项 | 10.991 ms | 0.031 ms | 99.7% |

追加测试预留了底层数组容量，排除了扩容开销；真实追加仍可能偶尔扩容。极短 Go 操作可能受内联和计时精度影响，因此没有把纳秒值作为用户可感知延迟。Markdown 帧包含布局与软件绘制，不代表真实 GPU 显示延迟。

|---|---:|---:|---|
| 30,000 条历史后一次追加，Go B/op | 1,687,556 B | 0 B | 不再重建全部行；已预留容量 |
| Markdown 缓存帧，Go B/op | 1,003,904 B | 756,448 B | 下降 24.6% |
| Markdown 分块，Go B/op | 68,149 B | 35,429 B | 下降 48.0% |
| 侧栏分组，Go B/op | 5,210,237 B | 4,017,854 B | 下降 22.9%；分配次数 1,424 → 1,444，哈希表增加少量分配 |
| 统计首次读取，Python 临时分配峰值 | 106,620,994 B | 16,834,320 B | SQL 过滤与分页，下降 84.2% |
| 无新增事件的统计刷新，Python 临时分配峰值 | 106,620,994 B | 9,304 B | 缓存已建立；仍查询最新序号 |
| 独立任务新增，Python 临时分配峰值 | 1,272,029 B | 2,262 B | 不构建无关任务图 |

内存权衡：不完全匹配历史的临时索引使 Go B/op 从 908,791 B 增至 1,154,840 B（+27.1%），换取避免平方级搜索。正常匹配路径不创建索引，分配量基本相同。工具 ID 索引长期占用 O(T) 指针空间，T 为当前会话工具数。上述分配指标均不是程序总内存或 RSS。

## 动画与帧节奏

旋转指示、运行状态点、思考光点与流式光标改为在已有元素树上重绘；布局变化与新内容继续走原有构建流程。帧定时以帧开始时间计算下一次截止时间，避免把本帧处理耗时再次加入等待周期。减少动态效果偏好仍生效。

真实 Windows / D3D11 窗口，每场景预热 600 ms、采样 3 秒，前后各独立执行 3 次。以下数值分别取三个运行摘要的中位数，不是合并样本的百分位数。

| 场景 | 重建次数：前 → 后 | 重绘回调数：前 → 后 | 帧间隔 p95：前 → 后 | 构建耗时 p95：前 → 后 |
|---|---:|---:|---:|---:|
| 仅运行指示，无新增内容 | 170 → 3 | 170 → 177 | 18.46 → 17.52 ms | 0.331 → 0.138 ms |
| 持续流式输出，已有 30,000 条历史和长回答 | 191 → 257 | 191 → 281 | 20.58 → 17.56 ms | 1.472 → 1.294 ms |
| 每 400 ms 展开或收起侧栏 | 167 → 102 | 167 → 179 | 20.15 → 17.93 ms | 0.438 → 0.330 ms |

仅运行指示的整页重建减少 98.2%；长流式场景 p95 帧间隔下降 14.7%。流式场景的帧数及构建次数增加：更便宜的重绘与内容更新、入场过渡交错，调度更及时。因此这组数据不能证明流式场景的总 CPU 或耗电下降。各运行的超过 25 ms 间隔计数见原始数据；三个运行摘要的中位数前后均为 0，不能据此声称消除了掉帧。

测量记录绘制回调间隔，覆盖上一帧提交、等待和本帧构建／布局／绘制；没有测量显示器扫描输出，不将这些回调数换算为显示 FPS。

## 代码简化与复杂度

| 模块 | 变更 | 时间复杂度与空间边界 |
|---|---|---|
| 对话追加与工具结果 | 完整恢复和增量追加共用 `AppendFeed`；工具 ID 哈希索引替代倒序寻找；维护思考占位数量 | 单条追加 O(N) → 均摊 O(1)；工具定位 O(N) → 平均 O(1)；索引 O(T) |
| 历史推理关联 | 保留正常倒序匹配快路径，遇到不匹配才构建签名索引与前驱链；游标只向前收缩 | 最坏 O(M×E) → O(M+E)，另计文本哈希成本；索引 O(E) |
| 侧栏 | 根目录去重、固定会话、项目分组与搜索统一为一次遍历，保留原顺序 | O(N×P) → O(N+P)，输出与哈希空间 O(N+P) |
| Markdown | 缓存组合后的文档；迭代分行、直接截取原文代替 Split/Join；克隆缓存键、清空淘汰槽位 | 缓存命中避免重复分块组合；缓存保留原来的 512 文档／8 MiB 源文本上限，单个超大文本例外规则不变 |
| 会话统计 | 提取 `SessionStatistics`，SQL 只读相关新增事件；512 条分页；deque 保留最近 32 个样本 | 首读与相关新增事件线性；无新增刷新为索引序号查询及固定样本复制；避免反复反序列化全部轨迹 |
| 轨迹内存 | 恢复时复制最后 300 条事件；实时淘汰时清空旧引用 | 显示轨迹保持 300 条；不再因尾部切片保留整份历史事件数组及数据 |
| 任务依赖 | 无依赖新增直接入库；有依赖时一次读取验证；显式栈 DFS 代替递归 | 独立新增避免 O(V+E) 扫描；有依赖 O(V+E)，显式栈 O(V)，10,000 层链不触发递归上限 |
| 附件完整性 | 导入与校验共用分段 SHA256 helper | 哈希仍 O(B)，额外整块拼接 O(B) 空间 → O(1) |
| 技能元数据 | frontmatter 维护累计长度代替反复求和 | 按行累计从平方级求和降为线性；读取上限与校验保持 |
| TUI | 反向索引扫描、`findLastIndex`、单次最大时间归约；循环追加代替大数组 spread | 展开查找最坏 O(N²) → O(N)、额外空间 O(1)；150,000 条待处理工具不再越过函数参数数量限制 |
| 原生动效 | 四处动效共用重绘循环，修改以模板同步到 vendor | 连续视觉效果不请求整树构建／布局；原来的周期、缓动、颜色与尺寸保持 |

按 15 个业务／UI 模板修改文件和 2 个新增业务 helper 统计，删除 176 行、加入 389 行，**净增加 213 行**。不含测试、基准工具、版本元数据、文档、`main.go` 诊断以及重复生成的 vendor；`shell.go` 包含绘制观察钩子。简化体现在去除重复计算、集中相同逻辑和明确缓存生命周期，并未以净代码行数减少作为目标。各文件计数保存在原始数据中。

## 复现与限制

硬件：AMD Ryzen 7 8845H（8 核／16 线程）、Radeon 780M、60 Hz 显示器，Windows 11 build 26200；Go 1.27.1、Python 3.12.4、Node.js 22.22.0。原生窗口逻辑尺寸 1500×940。合成数据固定，不包含个人会话或模型请求。

从仓库根目录运行 Python 基准：

```powershell
.venv/Scripts/python.exe scripts/benchmark_optimizations.py --output python-benchmark.json
```

Go 与 TUI 基准：

```powershell
Push-Location desktop/native
go test -run '^$' -bench 'BenchmarkOptimization|BenchmarkSessionGroups' -benchmem -benchtime=100x -count=5
go build -o ../../output/native/MiniCode-benchmark.exe .
Pop-Location
output/native/MiniCode-benchmark.exe -animation-benchmark animation.json -theme light
Push-Location tui
npx tsx scripts/benchmark_optimizations.ts tui-benchmark.json
Pop-Location
```

动画诊断使用隔离 fixture；此参数没有默认开启。基线 Python 从基线归档导入旧代码，使用同一脚本；基线 Go 复制同一 benchmark 与纯 `groupSessions` helper 供基准编译，基线界面没有调用新 helper；原生前后程序均加入同一绘制观察钩子。

统计合成数据有 5,000 个事件，其中 500 个回答、500 个工具开始及 4,000 个工具输出，输出字段约 10 KB。首次缓存建立和无新增刷新分开记录。Python 分配峰值用独立的一次 `tracemalloc` 测量，未混入速度计时。TUI 速度是每组 10 次调用的平均值，再取七组中位数。

结果会随数据、硬件与后台负载变化。这些指标验证客户端开销改善，不能推断网关或模型 TPS 提高，也未测量整机 CPU、RSS、启动耗时、功耗或输入到显示器延迟。
