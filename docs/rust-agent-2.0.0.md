# Rust Agent 2.0.0 迁移与验收

整个 Agent 后端、项目命令、评测宿主与报告生成改为 Rust。TypeScript + Ink TUI、Go / MyGo Desktop 保持现有技术栈、界面组件、主题和交互。前端只修改后端启动位置和包内工具 PATH。

Python 核心、Python 测试、解释器依赖与打包脚本已删除，旧 Python TUI 与 Electron 对照实现清除。当前源码只保留 Rust 后端、现用前端、Node.js 评测夹具和所需构建工具。历史性能报告保留为旧版证据。

## 功能兼容

| 功能 | 验证方式 |
| --- | --- |
| NDJSON v2、多会话、取消与审批 | 真实后端集成与前端桥接测试 |
| OpenAI / Anthropic 流、工具、媒体与用量 | 本地 HTTP 服务、碎片 UTF-8、重试与取消 |
| 文件读写、Diff、大文件搜索、命令与归档 | 原生工具、工作区边界、分页、后台输出与时间预算 |
| SQLite、任务 DAG、记忆、恢复 | schema 3→7、未来版本拒绝、未知副作用不重放、结果日志恢复 |
| 指令、技能、插件、本地资源与 MCP | 指令顺序、摘要冻结、插件锁、stdio / HTTP 测试 |
| 子助手 | 工具子集、审批路由、证据验证、累计用量、只读并发 |
| 内置评测 | 20 道题 × B0/B1/B2；3 场景含验收失败续跑，独立隐藏断言 |
| UI | Ink 原有测试、MyGo 快照及交互测试，实际安装窗口烟测 |

旧 schema 3–7 继续使用原 SQLite 格式和用户目录。模型配置、附件及项目记忆保持原身份摘要。现有更新公钥不变，更新替换整个 runtime 目录。

## 简化与优化

以 v1.3.2 的 `cdda80bc` 为基线，后端实现与内置资源从 76 文件、14,972 行降到 29 文件、11,256 行，减少 **24.82%**；统计不包含新 Rust 单元测试。Python 核心拆分模块合并为 20 个 Rust 模块，共用模型类型、错误处理、权限、持久化和进程管理。

清除的 Electron 对照实现、测试和前端构建配置包含 71 个源码文件、5,844 行。应用源码总计由 53,797 行降到 28,052 行，减少 **47.86%**；这个范围包含测试和构建脚本、排除 vendor，因此减少量也包含淘汰实现及重写的测试，不能全部算作业务逻辑简化。锁文件、文档和二进制资源不计入代码行数。当前受版本管理的 `.py` / `.pyi` 文件数为 **0**。

- 一个原生可执行文件统一 CLI / bridge / runtime / eval，移除解释器和 Python 依赖树。
- 工具 schema、正则和模型目录缓存后复用；SSE 参数以字符串缓冲区追加，避免逐片重建 JSON 字符串。
- 工具调用 / 结果配对一次线性扫描，目录分页采用确定性 DFS；任务依赖用线性图遍历，任务解锁用集合 SQL。
- 大文件编辑与搜索借用文件映射，分页有界读取；长输出写磁盘并保留预览。归档游标最多缓存 16 文件 × 64 检查点，连续翻页不重复扫描完整前缀。
- 状态轮询复用上下文摘要和增量统计；只读工具最多并发 4 个，只读子助手最多并发 2 个。命令 / MCP 的进程树由 OS 管理并回收。
- 发行构建使用优化、LTO、符号裁剪及静态 CRT；生产 Ink 依赖继续去掉类型声明与 source map，许可和运行数据保留。

线性配对使用哈希计数，时间 O(B)、额外空间 O(U)，其中 B 为消息块数、U 为工具调用 ID 数。任务环检测采用迭代 DFS，时间 O(V+E)，避免递归深链的栈溢出。分页缓存有数量上限；字符串流分片追加的累计工作量随响应字节数线性增长。这些是当前实现的复杂度说明；v1.3.2 已有部分线性优化，不能将此次全部收益归因于复杂度阶数下降。

## 测量方法

使用 v1.3.2 实际发行的 Python 3.12.12 环境作为基线，在同一台 Windows x64 机器、独立空白用户目录下与新发行 Rust 程序交替测量。离线脚本避免网络与模型生成时间干扰。

`scripts/benchmark-agent.mjs` 测量冷启动到首次 getState、25 轮模型 / 48 次只读工具、2000 条各 10k 字符历史，以及活动会话状态轮询。每项 7 次，报告中位数，并记录进程工作集、私有提交、峰值工作集及 CPU 秒。安装器与安装内容直接按最终产物字节计数。

测试机器：Ryzen 7 8845H（8 核 / 16 线程）、Windows 11 build 26200、15.29 GiB 内存、Node.js 22.22.0。冷启动指新建进程，没有清空 OS 文件缓存。两版交替测量，每对样本反转顺序；测量时没有同时运行本任务的构建或测试。这里使用发行构建的 MSVC 程序，原型 GNU 构建不计入结果。

## 实测结果

| 指标 | v1.3.2 Python | v2.0.0 Rust | 减少 |
| --- | ---: | ---: | ---: |
| Windows 安装器 | 82.28 MiB | 55.24 MiB | 32.86% |
| 安装内容 | 328.74 MiB | 210.98 MiB | 35.82% |
| 安装内容文件数 | 12,767 | 3,321 | 73.99% |
| 新进程启动 → 首次状态 | 993.74 ms | 28.26 ms | 97.16% |
| 首次状态后空闲工作集 | 76.08 MiB | 7.36 MiB | 90.33% |
| 25 轮 / 48 次读取耗时 | 365.65 ms | 181.69 ms | 50.31% |
| 上述场景工作集 | 77.86 MiB | 11.59 MiB | 85.11% |
| 上述场景累计 CPU（含启动） | 1.1719 s | 0.1875 s | 84.00% |
| 20M 字符历史读取耗时 | 1139.52 ms | 1008.09 ms | 11.53% |
| 历史读取峰值工作集 | 143.30 MiB | 52.87 MiB | 63.10% |
| 活动状态轮询 | 1.6245 ms | 0.0831 ms | 94.88% |
| 轮询场景工作集 | 104.30 MiB | 31.42 MiB | 69.87% |

安装内容按完整更新归档内的程序文件计数，不含安装器、更新资产、生成的卸载器或用户数据。旧版 344,713,612 B，新版 221,227,365 B；安装器分别为 86,275,104 B 与 57,924,627 B。Rust Agent 为 12,661,760 B（12.08 MiB），不再分发旧 Python 目录的 137,965,324 B。Git 与 Node.js 的安装字节数不变，仍是安装体积的主要部分。

内存来自 Windows `Get-Process` 的工作集、峰值工作集和私有提交，单位 MiB = 2²⁰ B；不是语言堆分配计数。CPU 取进程累计秒数，包含启动和初始化，不能当作纯工具循环的 CPU 降幅。历史读取耗时包含序列化、IPC 和客户端解析。

七次原始样本、私有提交、组件字节数、文件摘要、代码统计与 UI 对照见 [原始记录](assets/rust-agent-2.0.0.json)。测量 Agent SHA256 为 `0b61cbcda6ae6505368ba692da300850893c025e85a5929f41b143573d5830e9`。

这些指标描述本地 Agent 开销，不能解释为远程模型生成或网络等待同幅提速；前端 Node / Go 进程的内存需与 Agent 单独区分。
