# CommandCode 真实模型评测（2026-09-23）

这批结果用于展示可追溯的端到端执行与失败处理。它不是 SWE-bench 成绩，也不足以证明 B2 比 B0 更有效。

## 任务与判分

`evals/tasks/` 的 20 个任务都是自建微型单文件 Python bug。每次运行复制干净的 `repo/`，使用独立 SQLite 会话和工作区。B0 是基础 Agent 循环；B2 加入上下文压缩与运行时 Goal 门。两组使用相同模型、工具、自动允许策略和任务预算。

宿主在模型停止后独立检查：Runtime 是否 `completed`、可见回归测试退出码、受保护文件哈希、`allowed_paths` 修改范围，以及 `evals/hidden_tests/` 中工作区外的断言。隐藏断言不复制给 Agent，失败详情也不进入模型续跑。20 组隐藏断言均经过“原始 bug 失败、参考修复通过”测试。隐藏判分是在原始 120 次运行结束后，针对保存的工作区追加的；没有重复调用 API。原可见判分保存在 `visible_pass`，新增判分在 `hidden_pass`，最终判分在 `pass`。

## 配置与结果

模型为 `deepseek/deepseek-v4.1-flash`，通过当前 CommandCode 网关调用。每任务每基线 3 次，共 120 次。运行按任务分组，先 B0 三次再 B2 三次，最多 4 个请求并发；每次任务上限为 10 轮、80,000 累计 token、120 秒。网关没有配置温度或 seed。单次工作区、SQLite trace 和判分记录保留在本机 `reports/eval-real-20260923/runs/`。

| 基线 | 最终通过 | 可见通过 | 隐藏通过 | 误报完成 | 首轮无响应超时 | Runtime 中位秒数 | Runtime P95 秒数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| B0 | 47/60 | 47/60 | 54/60 | 0 | 3 | 65.765 | 120.031 |
| B2 | 51/60 | 51/60 | 58/60 | 0 | 1 | 67.953 | 120.032 |

B0 的 `time_budget` 为 13 次，B2 为 9 次；其中分别有 3 次和 1 次在首轮没有收到模型响应。所有超时都计入端到端成功率分母。B0 的记录输入/输出 token 合计分别为 752,531/35,413；B2 为 749,751/34,968。部分请求没有完整 usage，不能把这些汇总当作精确账单；没有已核实的当日网关单价，因此费用记为未知。`seconds` 在该批原始记录里只计 Agent Runtime，未包含末尾宿主评分；P95 在 60 次样本上仅作描述。

## 解释范围

这批任务都很小，压缩事件为 0；B2 的通过运行有 51 次 Goal 检查，未观察到因 Goal 失败后继续修复带来的可归因收益。`queue_fifo` 的 B0 三次均在时长上限终止、B2 三次通过；`string_format` 则是 B0 三次通过、B2 仅一次通过。4 并发和先 B0 后 B2 的启动顺序会影响网关排队。47/60 与 51/60 的差距不能归因为压缩或 Goal 门的效果。

本次运行开始时工作树已有未提交改动，执行期间又补了功能和文档；记录中的 Git HEAD 不能单独重建那一刻的完整代码。因此这批结果是可审查的**实测记录**，不是可字节级复现的最终发布基线。固定提交或源码快照后以串行、交替顺序重新运行全部 20 题，才足以做严格对照；用户已决定本轮不再追加这批 API 调用。当前微型题集也不能代表跨文件开发、大仓库排查或不可信代码的安全边界。

为补足机制覆盖，另提供 [三个补充场景](../evals/scenarios/README.md)。它们的离线脚本重放结果为 B0 2/3、B1 2/3、B2 3/3，其中 `counter_retry` 的 B2 确实走了验收失败续跑。它们不计入本页 120 次真实模型结果。
