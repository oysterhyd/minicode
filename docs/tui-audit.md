# TUI 审查与修复记录

审查范围为 React + Ink TUI、Python bridge 的 TUI 配置路径以及 CLI 启动入口。
逐项检查源码和实际事件协议，独立编写复现场景；没有读取或运行已有测试文件作为修复依据。

| 问题 | 修复结果 | 主要位置 |
|---|---|---|
| 快速提交在 React 提交状态前重复启动任务 | 接受状态转换时同步更新引用，序列化启动请求 | `App.tsx` |
| 排队消息被下一条覆盖 | 按 FIFO 保存多条消息 | `App.tsx` |
| 完成事件先于启动请求回包，下一条任务错误排队或丢失 | 请求结束与完成事件共同控制队列派发 | `App.tsx` |
| 取消、预算暂停、模型错误后自动启动排队任务 | 只在正常完成后自动派发，其余保留输入供手动发送 | `App.tsx` |
| 启动未完成时 Ctrl+C 无法取消随后启动的任务 | 回包后再次应用尚未完成的取消请求 | `App.tsx` |
| `/continue` 在快速完成后留下虚假的忙碌状态 | 先标记启动，再接受完成事件，不在回包时重新标记忙碌 | `App.tsx` |
| 慢速斜杠命令期间提交的消息无法继续发送 | 命令成功完成后派发期间排队的消息 | `App.tsx` |
| 初始化阶段不能退出，快速两次 Ctrl+C 不可靠 | 退出按键独立于初始化；退出确认使用同步时间戳 | `App.tsx` |
| Tab 补全直接执行命令 | Tab 只补全文字；Enter 执行 | `App.tsx`, `slash.ts` |
| 补全覆盖完整参数、部分选项不能正确确认 | 区分完整参数、前缀补全与键盘选择；保留 `skill off` 参数 | `App.tsx`, `slash.ts` |
| 恢复不同工作区会话后仍向旧工作区发送 | 使用持久化会话的工作区，刷新对应技能 | `App.tsx` |
| `/new` 保留旧会话的计数和状态 | 刷新新会话状态，重置显示与展开状态 | `App.tsx` |
| 恢复菜单使用八位 ID 可能碰撞，会话列表过期 | 补全发送完整 ID，在回合结束后刷新列表 | `slash.ts`, `App.tsx` |
| 过期状态请求和异会话事件污染当前界面 | 按会话与状态请求版本校验结果 | `App.tsx`, `feed.ts` |
| 重复按审批键会多次提交，审批结果匹配过宽 | 锁定待处理审批，以调用 ID 匹配决定 | `App.tsx`, `feed.ts` |
| 静态区冻结可变工具组，后续行越过未完成工具 | 只冻结有序且不可变的前缀，等待工具组边界确定 | `transcript.ts` |
| 流式 Markdown 分块导致标题、列表、引用链接变化后漏行；通知打断流式文本 | 保留整条文档直到完成，最终内容在原位置更新 | `transcript.ts`, `feed.ts` |
| 模型重试保留错误的部分回答，助手回答与提问相同时被隐藏 | 清理重试的部分文本；保留真实助手消息 | `feed.ts`, `transcript.ts` |
| 清屏后 Ink 在窗口变化时重新播放旧对话 | 清除终端显示和渲染器静态缓存 | `terminal.ts` |
| 长回复和展开输出把输入区挤出可见范围；部分展开输出重复显示 | 限制动态区域高度，显示流式尾部；完成后输出全文，排除重复展开 | `App.tsx` |
| Delete 执行退格，组合字符和 emoji 被拆开 | 区分 ASCII DEL 和 CSI Delete，按字素簇编辑 | `terminal.ts`, `caret.ts` |
| 中文、emoji、组合音标的宽度与换行光标位置不一致 | 使用终端字素宽度，按显示列换行，布局后更新 IME 光标位置 | `format.ts`, `caret.ts`, `Prompt.tsx` |
| 粘贴标记进入输入，粘贴中的控制键触发操作；PTY 合并文字和 Enter 时无法提交 | 处理 bracketed paste；粘贴外恢复合并的控制键事件 | `terminal.ts` |
| 历史工具结果缺少事件时不显示；未执行工具被显示为成功 | 从持久化工具结果回填，标记未完成调用 | `types.ts` |
| 安静工具失败被折叠，技能失败却显示成功或绿色 | 保留失败工具及错误输出，使用实际执行结果 | `transcript.ts`, `ToolLine.tsx` |
| Markdown 公式预处理修改代码字面量，嵌套引用和代码列表丢失，编号拼接错误 | 保护代码区域，递归渲染嵌套块，按数值生成编号 | `markdown.tsx` |
| 宽表格在窄终端错位，标题和状态栏超宽 | 宽表格转为逐字段展示；按可用列数截断摘要 | `markdown.tsx`, 各显示组件 |
| 非法数字和缺失参数通过启动解析 | 校验有限数值、整数轮数与参数值 | `args.ts` |
| provider 被忽略，脚本未隐式选 fake，脚本拼写错误被忽略 | 明确选择并校验 provider；脚本驱动 fake，严格校验脚本字段 | `desktop/bridge.py` |
| 相对验收路径在 bridge 的 cwd 下解析，资源目录忽略传入环境 | 在启动端解析路径，读取实际启动环境的资源目录 | `index.tsx`, `launch.ts` |
| bridge 退出、管道失败或协议失效后新请求继续挂起 | 标记连接失败，拒绝当前及后续请求 | `bridge.ts` |
| 退出直接杀 Python，遗留工具或 MCP 子进程 | 优先 EOF 清理，超时后终止进程树；主入口等待清理结束 | `bridge.ts`, `launch.ts`, `index.tsx` |

外观保留启动大字横幅，采用暖橙强调色、对话正文与工具摘要、横线输入区和低干扰状态栏。
横幅在窄终端使用紧凑字形或上下两行排布，避免大字折行错位。
保持键盘操作可见，失败状态同时使用文字和符号。颜色遵循终端的 `NO_COLOR` 设置。

验证结果：TypeScript 构建通过；新增独立回归与真实 bridge 用例 **35/35 通过**。
真实 bridge 用例包括脚本选模、审批写入、预算暂停后继续、取消审批、历史读取和正常退出；
Windows 用例确认 EOF 无响应时父进程与后代进程均退出。
另在 Windows ConPTY 中核对中文输入、光标定位、消息提交及终端模式恢复，检查了 100 列与 52 列的实际组件渲染帧。
模型网络请求没有用于本次验证。

在仓库根目录运行构建与独立检查：

```powershell
npm run build --prefix tui
$env:MINICODE_TUI_BRIDGE_TEST = '1'
npm run test:audit --prefix tui
```

真实 bridge 检查需要项目的 Python 依赖。未设置该环境变量时跳过四个真实 bridge 用例。
Ink 固定为 `6.8.0`：其公开 `clear()` 不清理静态缓存，相关缓存访问集中在 `terminal.ts`，
升级 Ink 时需要核对该接口并运行清屏、窄窗口与光标回归。
