# MiniCode 1.3.2 代码审查、简化与性能优化

基线为 1.3.1（`89543a8a44e475d9875f847aa05bfbc5bcc66e59`），2026-10-12 在同一台 Windows 11 / Ryzen 7 8845H 机器测量。保持现有布局、功能、权限规则、数据库 schema 7 及模型协议，继续优化客户端的数据处理和分配开销。

## 实测耗时

Python 为一次预热、7 次独立计时的中位数，临时分配峰值另用一次 `tracemalloc` 测量。Go 每组 100 次、独立重复 5 组，表中取组平均值的中位数；TUI 为两次预热、7 组，每组调用 100 次。

| 固定工作负载 | 1.3.1 | 1.3.2 | 耗时下降 |
|---|---:|---:|---:|
| 20 MB 命令日志提取末尾 | 69.140 ms | 0.163 ms | 99.8% |
| 13 MB Unicode 文本提取 50 KiB UTF-8 前缀 | 10.266 ms | 0.141 ms | 98.6% |
| 读取 2,000 条消息，每条文本 10 KB | 58.886 ms | 43.162 ms | 26.7% |
| 读取 2,000 条事件，每条数据 10 KB | 55.137 ms | 40.633 ms | 26.3% |
| 1,200 个交互单元，工具结果跨越所有候选压缩边界 | 2,213.426 ms | 3.682 ms | 99.8% |
| 1,200 个正常配对的交互单元，归档早期历史 | 7.622 ms | 5.427 ms | 28.8% |
| 无 ripgrep 时，从 80,000 行中取前 100 个匹配 | 5.868 ms | 0.683 ms | 88.4% |
| 同一文件完整扫描，没有匹配 | 98.227 ms | 80.362 ms | 18.2% |
| 320×213 缩略图的双线性采样 | 5.895 ms | 2.669 ms | 54.7% |
| 60,000 条 Git 状态记录，含 30,000 个重命名 | 1.845 ms | 1.255 ms | 32.0% |
| Git numstat，30,000 组重命名及二进制记录 | 6.443 ms | 2.828 ms | 56.1% |
| 10,000 行统一 Diff 解析 | 0.224 ms | 0.193 ms | 13.8% |
| TUI 在 30,000 条历史后更新一个流式片段 | 0.281 ms | 0.099 ms | 64.8% |

缩略图计时只包含采样，不包含文件读取、图片解码或上传 GPU。Git numstat 压力输入重复使用两个路径，字典最终只有两项；此项突出解析临时分配的成本，实际不同路径的结果字典仍占 O(P) 空间。TUI 仍复制记录数组以保留 React 状态不可变语义，时间和空间复杂度仍为 O(N)，改进来自原生数组复制及减少 JavaScript 回调。

## 代码简化与复杂度

| 模块 | 简化及优化 | 时间与空间 |
|---|---|---|
| 命令输出、文件及归档预览 | 在分行和编码前限定候选前缀／尾部，复用原有输出 helper | 对已有输入的额外处理从 O(C) 收敛到 O(B)，B 为输出预算；保留所有 splitlines 换行及 Unicode 边界行为 |
| 搜索回退路径 | 目录类型只检查一次；按 16 Ki 字符分块读取，替代整文件读取和完整行列表 | 时间 O(已读字符)，达到匹配上限后停止；额外空间 O(块大小＋最长逻辑行＋结果)，长行片段最后统一合并，避免重复拼接 |
| SQLite 会话、消息、事件及附件清单 | 七处读取直接迭代 cursor；先截取标题预算再分行 | 仍返回原来的完整对象列表 O(N)，去掉同时存活的全部序列化行；排序、校验和事件过滤不变 |
| 上下文压缩 | 归档和结构化摘要共用 `_paired_prefix`；删除两处逐个候选重复扫描 | 最坏 O(U×M) → O(M＋U)，U 为候选单元数，M 为工具块及消息总量；额外 O(T) 计数和违规 ID 集合 |
| 图片缩略图 | 常见 PNG / JPEG 位图直接访问具体颜色值，共用原有 RGBA 转换 | 采样仍 O(W×H)，消除每个像素的四次颜色装箱；透明度、非零图片原点及插值结果一致 |
| 文件列表、Git 状态、numstat 与 Diff | 惰性分隔器替代完整拆分数组；numstat 使用 Cut，二进制 `-` 不进入整数错误解析 | 线性解析；文件列表达到 5,000 个匹配后停止迭代；结果字典和状态列表仍按原规模保留 |
| TUI 流式回复与工具事件 | 七处单条记录替换共用 `replaceItem`，slice 后只更新目标记录 | 保持 O(N) 数组复制、对象不可变和历史对象引用；减少逐条 callback |
| 发行构建 | 单独的元数据裁剪脚本；烟测加载真实 TUI 主入口 | 只删除类型声明及 source map，不改变运行模块、WASM、package.json、许可及三套内置运行环境 |

业务和打包代码共修改 **11 个文件，加入 178 行、删除 73 行，净增加 105 行**，不计版本、文档、测试和基准。简化发生在公共处理路径、去除重复扫描及合并记录更新；新算法、分块边界处理和安装包裁剪需要代码，未将“简化”描述为总代码行数减少。

## 复现

基线源码使用 `git archive 89543a8` 解压。Python 基准可分别指定根目录；Go 基准文件复制到基线后只执行 benchmark，不修改基线业务代码。Python 3.12.4、Go 1.27.1、Node.js 22.22.0，所有输入为合成数据，没有调用付费模型或使用个人会话。

```powershell
.venv/Scripts/python.exe scripts/benchmark_132.py --root <基线目录> --output before.json
.venv/Scripts/python.exe scripts/benchmark_132.py --output after.json
Push-Location desktop/native
go test -run '^$' -bench 'BenchmarkThumbnail132|BenchmarkGit.*132|BenchmarkDiffParser132' -benchmem -benchtime=100x -count=5 . ./internal/workspace ./internal/content
Pop-Location
Push-Location tui
node_modules/.bin/tsx.cmd scripts/benchmark_132.ts <仓库目录> <输出.json>
Pop-Location
```

[原始基准、快照对照及代码行统计](assets/performance-1.3.2.json)。结果受数据和机器负载影响，不能推断模型生成速度、网络等待或整个任务完成时间同比提高。
