# minicode 对齐 Pi Agent 的工具输出与运行预算方案

> 日期：2026-09-23  
> 状态：方案，尚未实施  
> 范围：文件读取、搜索、列目录、命令输出、TUI 展示、上下文压缩和子代理预算

## 目标

让 minicode 的工具输出和运行循环采用接近 Pi Agent 的默认值，同时保留现有会话存储、权限判断和文件编辑机制。模型的 1M 上下文窗口是**单次请求**可容纳的上下文，不是整个任务的累计 token 上限；工具输出仍需分页或截断，以免一次调用占满上下文。

子代理只额外限制**可用工具**。它使用与主对话相同的模型、上下文处理及用户显式配置的预算，不再另设 8 轮、10,000 token、90 秒等固定上限。

## 现状与目标值

| 项目 | 当前行为 | 目标行为 |
| --- | --- | --- |
| `read` | 默认 200 行；单页约 19,800 字符；支持 `offset` / `cursor` | 默认最多 2,000 行或 50 KiB UTF-8，取先到的限制；保留偏移、游标和续读提示 |
| `grep` | 默认且最多 100 条；单行约 200 字符；总输出约 20,000 字符 | 默认 100 条、单行最多 500 字符、总输出最多 50 KiB；允许调用方提高匹配条数，但仍受 50 KiB 输出限制。接受文件或目录路径；默认大小写规则与 Pi 对齐，并在帮助中说明 |
| `ls` | 递归列出，默认且最多 500 项；总输出约 20,000 字符 | 默认列出当前目录的 500 项、最多 50 KiB；需要递归时显式指定，以免既有调用无意遍历整棵目录 |
| `bash` | 默认超时 60 秒、最大 300 秒；前 10,000 字符以内的捕获结果随后还可能被全局规则缩成 1,000 字符 | 展示末尾最多 2,000 行或 50 KiB；截断时完整输出落入 artifact，前台和后台命令使用同一规则。默认不设命令超时，仍支持调用方显式设置和用户取消 |
| 全局输出缩略 | 超过 4,000 字符时，模型只见前 1,000 字符和 artifact 引用 | 移除统一 4,000/1,000 字符缩略；各工具按自己的输出规则提供可读部分，并保留完整 artifact。`read_artifact` 分页结果不再被二次缩略 |
| TUI 工具卡 | 事件只带约 500 字符预览和最多 4,000 字符详情，展开仍看不到完整结果 | 卡片先显示摘要；用户展开时按 artifact 引用读取完整结果，支持滚动或分页。明确标出“已截断”和续读入口 |
| 主循环预算 | 常用命令默认每段 20 轮、600 秒、累计 token 不限；CLI/TUI 会在部分停止状态下自动续跑 | 默认轮数、时长、累计 token 均不设上限；保留用户显式设置的预算。将 `0` 定义为无限制，并修正当前时长为 `0` 会立刻到期的实现 |
| 上下文压缩 | 估算占用到窗口的 80% 时触发；保留最近 4 轮 | 以“上下文窗口减去 16,384 token 预留”为触发线，优先保留最近约 20,000 token；归档旧工具输出，维持消息及工具调用配对 |
| 子代理 | 独立 8 轮、10,000 token、90 秒；任务文本和回报字段另有截断 | 不设子代理专属数值上限；共享主对话显式预算与取消信号，沿用相同上下文压缩和输出规则。仅允许只读工具 |

`bash` 可保留现有 100 MB 原始输出捕获配额作为本机磁盘与进程保护。达到配额时应明确报告并保留已捕获内容；它不应充当正常的模型可见输出阈值。

## 子代理运行规则

1. 工具白名单保持为 `read`、`ls`、`grep`、`read_artifact`。即使主对话使用 `bypass` 权限，子代理也不能调用 `bash`、`edit`、`write` 或再次委派。
2. 子代理保留独立消息历史、会话记录和事件链，并关联到主对话；模型、提供方、上下文窗口、压缩策略和工具输出策略与主对话一致。
3. 主对话未设置预算时，子代理也没有隐藏的轮数、累计 token 或时长上限。主对话显式设置预算时，父子代理共同消耗一份预算；每次模型调用完成后实时计入，避免并发子代理分别用满同一余额。
4. 主对话取消时立即向子代理传播取消。若显式分段预算导致暂停，应记录进度并从原子代理会话续跑，不因到达 8 轮一类的内部阈值直接判失败，也不重新执行已完成的工具调用。
5. 移除子代理任务文本 4,000 字符及回报中摘要、发现数量、引用数量等固定小截断。给主对话的回报仍需有清晰摘要与证据引用；超过通用工具输出额度的原文保存为 artifact，按需读取。

## 实施顺序

1. **工具输出。** 调整 `ToolLimits` 与 `read`、`grep`、`ls`、`bash` 的分页和截断规则；统一前后台命令的完整输出归档；取消全局二次缩略，并让 TUI 能按需打开 artifact。保留现有 `offset` / `cursor` 的含义，避免破坏旧会话的续读操作。`ls` 默认递归行为改变时，同步更新工具说明。
2. **循环和上下文。** 将默认预算改为无限制，保留显式预算；更新 CLI 帮助、配置说明和断点恢复逻辑。采用 Pi 风格的压缩阈值与最近上下文保留量。先检查提供方请求的 `max_tokens`：当前 DeepSeek v4.1 Flash 目录值为 384,000，不能在 1M 窗口临近末端仍按该值预留输出；应根据本次提示词占用动态计算可请求的输出额度。
3. **子代理。** 删除专属 8 轮 / 10,000 token / 90 秒预算和回报字段的小额度截断；接入共享预算账本、取消传播、相同压缩策略与续跑机制；保留只读白名单和独立追踪。
4. **文档与迁移。** 更新工具 schema、帮助文本、配置文档和事件字段说明。注明 `ls` 递归、`grep` 大小写、`bash` 默认超时等行为变化；已有显式参数继续按原语义执行。

## 验收条件

- 大文件读取在 2,000 行或 50 KiB 停止并给出可用的续读位置；超长单行也不会无限制进入模型上下文。
- `grep` 默认 100 条，单行和总输出达到阈值时均有清楚的截断标记；文件和目录路径可用。`ls` 默认 500 项，并能显式递归。
- 大量标准输出、错误输出及后台命令均展示尾部 2,000 行或 50 KiB；完整内容可从 artifact 读取；TUI 展开能看到归档内容。
- 未设置预算的主对话和子代理可运行超过 20 / 8 轮及 10,000 累计 token；子代理仍拒绝写入和命令执行。
- 主对话设置显式预算时，父子调用共同计费并在预算耗尽时停止；取消和恢复不会重复执行已完成的调用。
- 在 1M 窗口模型上做实际网关调用验证：压缩、动态输出额度和上下文溢出恢复能正常协作。token 估算目前采用字符数除以 3，需用实际 usage 校准，并保留溢出兜底。
- 运行相关单元和集成测试，再运行完整测试集；出现行为变化时更新相应断言和文档。
