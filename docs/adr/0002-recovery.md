# ADR 0002: 崩溃恢复采用保守副作用语义

状态：已采用（2026-09-23）

## 背景

进程可能在工具执行前、执行后结果写入前、结果写入后任一点终止。Shell 和写文件不能安全地通过旧调用 ID 自动重放；SQLite 事务也无法和外部进程副作用组成一个原子事务。

## 决策

消息、工具事件和会话计数持久化。恢复时仅重新执行悬空的内置只读调用，并重新检查权限；悬空写入、Shell 和 MCP 调用标记 `SIDE_EFFECT_UNKNOWN`，要求模型先核实。已经持久化的 `tool_result` 不重放。后台进程重启后视为失联，不凭旧 PID 继续管理。

## 后果与证据

该设计保证未知写入不会未经核实重复发生，但无法承诺 exactly-once。`tests/test_crash_windows.py` 在三处边界注入进程级异常，验证写入次数和恢复分支。未知状态会暂停完成判断，保留 trace 供审查。
